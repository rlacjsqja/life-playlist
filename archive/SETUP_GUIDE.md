# 내 인생 플레이리스트 - 설치 가이드

총 3단계예요. 다 합쳐서 10분이면 충분합니다.

---

## 1단계. 구글 시트를 데이터 저장소로 만들기

1. [sheets.google.com](https://sheets.google.com) 에서 새 스프레드시트를 하나 만드세요. (이름은 자유롭게, 예: "내 인생 플레이리스트")
2. 메뉴에서 **확장 프로그램 → Apps Script** 를 클릭하세요.
3. 기본으로 열려있는 `Code.gs` 안의 내용을 전부 지우고, 함께 드린 **`Code.gs`** 파일의 내용을 전부 붙여넣으세요.
4. 상단의 저장(디스크 모양) 아이콘을 눌러 저장하세요.

## 2단계. 웹앱으로 배포해서 URL 발급받기

1. Apps Script 화면 오른쪽 위 **배포 → 새 배포** 클릭
2. 톱니바퀴(⚙️) 아이콘 → **웹 앱** 선택
3. 설정값:
   - **실행 사용자**: 나(본인 계정)
   - **액세스 권한이 있는 사용자**: 전체 허용 (Anyone)
4. **배포** 클릭 → 권한 승인 창이 뜨면 본인 계정으로 승인 (Google이 "확인되지 않은 앱" 경고를 띄우면 "고급" → "이동" 눌러 진행하면 됩니다. 본인이 만든 스크립트라 안전해요)
5. 배포가 끝나면 `https://script.google.com/macros/s/여기에긴문자열/exec` 형태의 **웹 앱 URL**이 나옵니다. 이걸 복사해두세요.

> ⚠️ 나중에 Code.gs를 수정하면 **배포 → 배포 관리 → 수정(연필 아이콘) → 새 버전** 으로 다시 배포해야 변경사항이 반영돼요.

## 3단계. 웹앱 URL을 index.html에 붙여넣기

1. 함께 드린 **`index.html`** 파일을 텍스트 편집기로 여세요.
2. `<script>` 태그 안, 아래 부분을 찾으세요.

```js
const CONFIG = {
  WEBAPP_URL: 'PASTE_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE'
};
```

3. `'PASTE_YOUR_APPS_SCRIPT_WEB_APP_URL_HERE'` 자리에 2단계에서 복사한 URL을 붙여넣고 저장하세요.

```js
const CONFIG = {
  WEBAPP_URL: 'https://script.google.com/macros/s/AKfycb.../exec'
};
```

## 4단계. 어디서든 접속 가능하게 올리기 (호스팅)

`index.html` 파일 하나만 있으면 되는 정적 웹페이지예요. 아무 곳에나 올려서 URL만 있으면 휴대폰, PC, 태블릿 어디서든 브라우저로 접속할 수 있어요. 가장 쉬운 방법 두 가지를 추천해요.

### 방법 A. Netlify Drop (가입 없이 30초, 추천)
1. [app.netlify.com/drop](https://app.netlify.com/drop) 접속
2. `index.html` 파일을 그대로 브라우저 화면에 드래그 앤 드롭
3. 즉시 공개 URL이 생성됩니다. 이 URL을 휴대폰 홈 화면에 추가하면 앱처럼 쓸 수 있어요.
   - iPhone: Safari에서 공유 → "홈 화면에 추가"
   - Android: Chrome에서 메뉴 → "홈 화면에 추가"

> 무료 계정 없이도 배포는 되지만, 나중에 파일을 업데이트하려면 무료 가입 후 같은 사이트에 새로 드래그하면 됩니다.

### 방법 B. GitHub Pages (이미 GitHub을 쓰고 있다면)
1. 새 저장소를 만들고 `index.html`을 업로드
2. 저장소 **Settings → Pages** 에서 배포(Branch: main, 폴더: /root) 설정
3. 몇 분 후 `https://아이디.github.io/저장소이름/` 주소로 접속 가능

## 다 되면 이렇게 써요

1. 검색창에 곡명, 가수명, 앨범명 중 아무거나 입력 (예: `dancing` 만 쳐도 자동완성 추천이 뜹니다)
2. 추천 목록에서 원하는 곡 선택 → 제목/가수/앨범/발매년도가 자동으로 채워짐. 각 항목 아래 작은 배지로 어느 음원사이트(iTunes/Spotify)에서 온 정보인지, 정규/싱글/편집반인지도 표시돼요.
3. 검색해도 안 나오는 곡은 검색창 아래 **"✏️ 검색 결과에 없나요? 직접 입력하기"** 를 눌러 제목/아티스트 등을 직접 입력해서 추가할 수 있어요.
4. 필요하면 메모나 별점 추가 후 **"플레이리스트에 추가"** 클릭
5. 목록은 구글 시트에 저장되므로, 다른 기기에서 같은 페이지에 접속해도 동일한 목록이 보여요

## (선택) 5단계. Spotify 연동으로 검색 범위 넓히기

iTunes Search API만으로도 앱은 정상 동작하지만, Spotify를 추가로 연동하면 국내 가수/앨범 검색 범위가 넓어지고 앨범이 정규/싱글/컴필레이션 중 무엇인지 더 정확하게 표시돼요 (Spotify는 이 정보를 명시적으로 제공하거든요).

1. [developer.spotify.com/dashboard](https://developer.spotify.com/dashboard) 에서 무료 계정으로 로그인 후 **Create app** 클릭 (앱 이름/설명은 아무거나, Redirect URI는 `https://localhost` 아무거나 입력해도 무방 — 이 앱은 로그인 기능을 쓰지 않아요)
2. 앱 생성 후 **Client ID**와 **Client Secret**을 확인
3. Apps Script 편집기로 돌아가서, `Code.gs` 안의 `setSpotifyCredentials` 함수를 찾아 `'YOUR_SPOTIFY_CLIENT_ID'` / `'YOUR_SPOTIFY_CLIENT_SECRET'` 자리에 방금 발급받은 값을 넣으세요.
4. Apps Script 화면 상단 실행할 함수 선택 드롭다운에서 `setSpotifyCredentials`를 고르고 ▶ 실행 버튼 클릭 (최초 1회만 하면 됨)
5. 다시 **배포 → 배포 관리 → 새 버전으로 배포** 해주세요 (Code.gs를 수정했으니 재배포해야 반영돼요)

> Client Secret은 Apps Script 서버 안에만 안전하게 저장되고, index.html(프런트엔드)에는 절대 노출되지 않아요.

## 참고: 왜 멜론·지니·벅스는 연동이 안 되나요?

멜론/지니/벅스/VIBE 같은 국내 음원 서비스는 외부 개발자가 쓸 수 있는 공식 검색 API를 제공하지 않아요. 비공식적으로 우회(크롤링)하는 방법도 있지만, 각 서비스 이용약관 위반 소지가 있고 앱을 배포/수익화하려는 계획과는 특히 안 맞아서 이 앱에는 포함하지 않았어요. 대신 iTunes(Apple Music 카탈로그)와 Spotify 두 곳을 합쳐서 검색 범위를 최대한 넓혔고, 그래도 없는 곡은 4단계처럼 직접 입력하면 돼요.

## 여러 사람에게 배포해서 피드백 받기 (v3부터 지원)

호스팅한 링크 하나를 여러 사람에게 공유해도, 각자 접속하는 순간 자동으로 "자기만의 목록"이 생겨요. 로그인이나 회원가입은 없어요 — 처음 접속하면 브라우저에 익명 코드(uid)가 하나 저장되고, 그 코드를 기준으로 목록이 나뉘는 방식이에요.

**알아두면 좋은 점**

- 화면 위쪽 "내 목록 전용 링크" 박스에 있는 주소가 그 사람만의 고유 링크예요. 이걸 북마크하거나 자신에게 카톡/메모 등으로 보내두면, 나중에 다른 기기에서도 그 링크로 들어가서 같은 목록을 이어볼 수 있어요.
- 이 링크를 다른 사람에게 그대로 보내면, 그 사람도 "내" 목록을 보고 수정할 수 있게 돼요 (같이 쓰는 공유 리스트처럼 활용도 가능). 반대로 그냥 배포 주소(uid 없이)로 새로 들어오면 그 사람은 완전히 새로운 자기만의 목록을 시작하게 돼요.
- **비밀번호는 없어요.** 링크만 알면 접근되는 구조라, 초기 피드백을 받는 용도로는 충분하지만 민감한 데이터를 넣는 용도로는 적합하지 않아요.
- 무료 Google Apps Script 계정 기준으로 하루 호출 한도가 있어서(대략 하루 URL 호출 2만 건 수준), 소규모 피드백 그룹(수십 명)에는 충분하지만 수백~수천 명 단위로 커지면 별도 백엔드로 옮기는 게 좋아요. 그 시점이 되면 알려주세요.
- **이전에 테스트로 넣었던 곡이 안 보일 수 있어요.** 이번 업데이트로 각 곡에 uid가 붙기 시작해서, uid 없이 저장된 예전 데이터는 필터링돼서 안 보여요. 구글 시트를 열어 "Playlist" 탭에서 예전 행들의 uid 칸에 본인의 uid(위 링크에 있는 `?uid=` 뒷부분)를 채워 넣으면 다시 보여요.

## (선택) 6단계. Google 로그인 붙이기 (v4)

익명 링크 방식만으로도 각자 목록은 분리되지만, 링크를 잃어버리면 복구가 안 돼요. Google 로그인을 붙이면 사람들이 링크를 따로 챙길 필요 없이 "구글 계정으로 로그인"만 하면 어느 기기에서든 자기 목록을 볼 수 있어요.

**먼저 4단계(호스팅)를 끝내서 최종 접속 주소를 확보한 다음 이 단계를 진행하세요.** (Google 로그인은 어떤 주소에서 접속했는지를 미리 등록해둬야 동작해요.)

1. [Google Cloud Console](https://console.cloud.google.com/) 접속 → 새 프로젝트 하나 생성 (이름 자유)
2. 왼쪽 메뉴에서 **API 및 서비스 → OAuth 동의 화면** 으로 이동
   - User Type: **외부(External)** 선택
   - 앱 이름/이메일 등 필수 항목만 채우고 저장
   - **게시 상태가 "테스트중"으로 유지됩니다.** 이 상태에서는 아래 "테스트 사용자" 목록에 직접 추가한 구글 계정만 로그인할 수 있어요 (최대 100명). 베타 테스트 규모에는 보통 충분하지만, 이 부분을 놓치면 친구들이 로그인 시도할 때 "확인되지 않은 앱" 차단 화면을 보게 돼요. **OAuth 동의 화면 → 대상(Audience) → 테스트 사용자**에서 피드백 받을 사람들의 Gmail 주소를 미리 추가해두세요.
3. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID** 클릭
   - 애플리케이션 유형: **웹 애플리케이션**
   - **승인된 자바스크립트 원본**에 호스팅 주소를 정확히 입력 (예: `https://your-site.netlify.app`, 끝에 슬래시(/)나 경로 없이 도메인만)
   - 만들기 클릭 → **클라이언트 ID** (`...apps.googleusercontent.com` 형태) 복사
4. 이 클라이언트 ID를 **두 군데**에 똑같이 붙여넣으세요.
   - `index.html`의 `CONFIG.GOOGLE_CLIENT_ID`
   - `Code.gs`의 `GOOGLE_CLIENT_ID` 상수
5. Apps Script를 **배포 → 배포 관리 → 새 버전으로 배포** 해주세요.
6. 호스팅 사이트에도 수정된 `index.html`을 다시 올려주세요.

> Client ID는 비밀값이 아니라 프런트엔드 코드에 그대로 노출되어도 괜찮아요. 실제 신원 확인은 로그인 시 발급되는 토큰을 Apps Script 서버가 구글에 직접 검증 요청해서 처리하기 때문에, 누군가 Client ID를 알아내도 다른 사람인 척 로그인할 수는 없어요.

로그인을 설정하지 않으면 화면에 로그인 관련 UI 자체가 나타나지 않고, 기존 익명 링크 방식 그대로 동작해요 — 언제든 나중에 추가해도 됩니다.

## 문제가 생기면

- **"검색 결과가 없어요"만 계속 뜬다** → 인터넷 연결 확인, iTunes Search API는 별도 키가 필요 없어서 보통 바로 됩니다.
- **저장 버튼을 눌러도 반영이 안 된다** → `index.html`의 `WEBAPP_URL`이 올바르게 붙여넣어졌는지, Apps Script 배포 시 "액세스 권한: 전체 허용"으로 설정했는지 확인하세요.
- **구글 시트를 직접 열어서 데이터를 봐도 돼요** → Apps Script가 자동으로 만든 "Playlist" 시트 탭에 모든 곡이 한 줄씩 저장됩니다.
- **Spotify 검색 결과가 안 뜬다** → `setSpotifyCredentials` 실행을 했는지, 그 후 Apps Script를 "새 버전"으로 재배포했는지 확인하세요. Spotify가 설정 안 되어 있어도 iTunes 검색은 정상 동작해요.
- **다른 사람 목록이 섞여 보인다 / 내 곡이 안 보인다** → `Code.gs`를 이번 버전으로 업데이트한 뒤 반드시 "새 버전으로 배포"를 했는지 확인하세요. 재배포 전에는 uid 구분 없이 모두가 같은 목록을 보게 돼요.
- **친구가 Google 로그인 시 "확인되지 않은 앱" 화면이 뜬다** → OAuth 동의 화면이 "테스트중" 상태인데 그 사람 Gmail이 테스트 사용자 목록에 없어서 그래요. Google Cloud Console → OAuth 동의 화면 → 대상 → 테스트 사용자에 추가해주세요.
- **로그인 버튼 자체가 안 보인다** → `index.html`의 `CONFIG.GOOGLE_CLIENT_ID`와 `Code.gs`의 `GOOGLE_CLIENT_ID`가 둘 다 실제 값으로 채워져 있는지, 오타 없이 동일한지 확인하세요. 둘 중 하나라도 placeholder(`YOUR_GOOGLE_CLIENT_ID...`)로 남아있으면 로그인 UI가 의도적으로 숨겨져요.
